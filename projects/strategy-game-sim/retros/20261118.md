### 1. The ticket-lint Invariants check never fires in this repo
Evidence: strategy-game-sim SGS-204. `reports/SGS-204-ticket-1.md` reports "ticket-lint passes" with
`Invariants: none`, at 20:54 on 11-17, 15 minutes after dd5541e (#130, the fix for retro issue #74)
landed. `reports/SGS-204-spec-gate-2.md` finding 3 then bounced it for that field. Today
`ticket-lint.py` exits 0 on `tickets/SGS-205-help-modal-headings-larger-than-body.md`: `Invariants: none`,
with `components/apps/aoe4-build-order/page-help.tsx` in Scope.
Root cause / escape point: tooling gap (the check exists and cannot match). Escape point: ticket (lint),
caught at spec-gate.
RCA: `read_invariants` splits a `Paths:` line on commas and strips whitespace only. Every `Paths:` line in
this repo's INVARIANTS.md wraps its globs in backticks (`` `components/apps/aoe4-build-order/**` ``),
so each compiled regex requires literal backtick characters and matches no path. A copy of the script
that also strips backticks reports, for SGS-205: "Invariants is `none` but Scope names
`components/apps/aoe4-build-order/page-help.tsx`, guarded by 'AoE4 Build Order Simulator'". A second gap
explains SGS-204's first draft: its Scope named files by bare name (`result-series.ts`,
`line-chart.tsx`), which no `Paths:` glob can match. cfb8965 (today) makes this lint the only spec check
for `low` and `standard` tickets. A broken check there now goes straight to the implementer.
Confidence: high - verified by running the script; the edit is mechanical.
Proposal (repo): `INVARIANTS.md` - drop the backticks on the four `Paths:` lines (lines 8, 23, 34, 50),
for example
```diff
-Paths: `pages/apps/aoe4-build-order.*`, `components/apps/aoe4-build-order/**`, `lib/aoe4-build-order/**`, `pages/api/aoe4-build-order/**`, `data/aoe4-build-order/**`.
+Paths: pages/apps/aoe4-build-order.*, components/apps/aoe4-build-order/**, lib/aoe4-build-order/**, pages/api/aoe4-build-order/**, data/aoe4-build-order/**
```
(this makes the lint fire today; keep it until the engine fix lands, then either form works).
Proposal (engine): Issue draft: ticket-lint: the Invariants check never matches backticked `Paths:` globs or bare file names
> **Problem.** `read_invariants` in `scripts/ticket-lint.py` compiles each comma-separated `Paths:` item
> after `strip()`. In a repo whose INVARIANTS.md writes `` Paths: `a/**`, `b/**` `` (the house style in
> WOTR_Combat_Simulator), each regex includes the backticks, so `Invariants: none` never errors. Evidence:
> the lint passes SGS-205 (`Invariants: none`, Scope names `components/apps/aoe4-build-order/page-help.tsx`,
> guarded by `components/apps/aoe4-build-order/**`), and passed SGS-204's first draft 15 minutes after
> #130 landed. Spec-gate then bounced SGS-204 for the field. Since cfb8965, `low` and `standard`
> tickets have no spec-gate, so nothing else catches it. A second gap: Scope often names files bare
> (`result-series.ts`) under a "paths under X" lead-in, and a bare name never matches a glob.
> **Suggested edit.** In `read_invariants`, take globs from backtick spans when the line has any, else
> split on commas; drop items with a space (trailing prose such as "and any new app"):
> ```diff
> -            globs = [g.strip() for g in m.group(1).split(",") if g.strip()]
> +            line = m.group(1)
> +            items = re.findall(r"`([^`]+)`", line) or line.split(",")

> `missing_at` already lists) before matching. Without `--spec`, warn on a bare name in Scope ("write a
> repo-relative path"). Add a test fixture with backticked `Paths:` and one with a bare name.

`tool_use` with no `tool_result`.

12 h stall.

> **Problem.** manage.md:176-180 tells a drive pass never to end its turn while a background agent runs,
> but `claude -p` has no way to wait on a background agent, so a turn that says "I'll wait for it" ends
> the pass and the agent dies. WOTR 2026-11-16: the M11 designer (14:14, rerun next pass, $2.85 lost) and
> the SGS-192 (opus) and SGS-197 implementers (22:27, relaunched 12 h later at $5.40 and $1.66).
