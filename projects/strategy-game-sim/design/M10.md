# M10: Technical design

AoE4 build order is a desktop page (mobile support removed). Exit criteria M10.1 to M10.5 in MILESTONES.md.
M10.5 is owner evidence. This doc designs M10.1 to M10.4. It removes code and tests; it adds one CSS
declaration, one acceptance spec and one helper constant. M11 (draft) builds its chart work on the one
layout this leaves.

## Summary

The two-column layout (Build | Results), today shown from 1200 px up, becomes the only layout. The
minimum supported width is 1200 px (OD1). Below it, the page section keeps the width it has at a 1200 px
viewport and the document scrolls sideways (OD2), so a phone sees the same layout as a 1200 px desktop.
Tabs, the `matchMedia` switch, the step-row card layout and every viewport breakpoint in the AoE4 CSS go.
The `build-editor` container queries are not narrow-only: they make the editor compact inside the
desktop column, so their compact values move into the base rules and the queries go. Specs that hold
narrow or tabs-layout cases are deleted or moved to desktop viewports first, while today's code still
passes them; then the code change lands with one new spec for the below-minimum behavior; then the docs.

## Behavior rules

| operation | case | rule |
|-----------|------|------|
| B1 render | viewport W ≥ 1200 | Two columns, Build left and Results right, both always shown, no tabs; the document does not scroll sideways (`scrollWidth ≤ innerWidth`). Tested at 1200 (first sample) and 1800 (last sample). |
| B2 render | 1199 ≥ W (first sample 1199, last tested sample 390) | The section is as wide as at W = 1200 (C4) and holds the same two-column layout; the document scrolls sideways by the overflow; vertical behavior is unchanged (run bar sticky with its 40dvh cap, columns fill the viewport below it and scroll on their own). The `Layout` header outside the section stays at the viewport width. Spec: at 1199 and 390, section width equals the width read at 1200, `scrollWidth > innerWidth`, `workbench-split` and both panels visible. |
| B3 render | at 390x844, no overlap | The run bar's bottom ≤ `workbench-split`'s top; `build-column`'s right ≤ `results-column`'s left; the textarea's client width ≥ 50% of `build-order-editor`'s width; every chart in `CHART_IDS` has a non-zero width. All read in one `evaluate`. |
| B4 resize | across 1200 in either direction | No remount, no new run, no layout change: only the sideways scroll appears or goes. Editor focus, text and an open step row are untouched (nothing switches, so there is nothing to carry). Spec: resize 1280 → 390 → 1280 with the textarea focused; focus and value kept, no simulate POST. |
| B5 first paint | server render and hydration | The server HTML is the two-column layout (C1); the client renders the same, with no hydration warning and no switch after load. |
| B6 open link | `?n=` or `?b=` load succeeds | The build loads and runs as today; nothing is selected and nothing scrolls (the old "Results is selected after the first run" rule is removed with the tabs). |
| B7 Results column | no result and no pin | Shows what the two-column layout shows in that state today (the `Results` heading and the compare panel); there is no disabled state. |
| B8 notice (OD2 = B only) | W < 1200 | `min-width-notice` is visible at scroll position 0 and lies inside the viewport (`right ≤ innerWidth`); at W ≥ 1200 it has `display: none`. It changes nothing else. |
| B9 view toggle | Results shown | Text and Table are never disabled by the Results column (C6). |
| B10 keyboard | whole page | Tab order follows DOM order: run bar controls, Build column, Results column; no positive `tabindex`. No tablist and no arrow-key handling in the workbench. Escape behavior elsewhere (save link) unchanged. |
| B11 editor | every width | One editor style: the compact values (0.875rem font, 4.7ch annotation column, finished time hidden in the gutter and still shown in the table view and its run cells). |
| B12 step table | every width | Rows are table rows (no cards); labels are inline and wrap when they do not fit; a table wider than the Build column scrolls inside `step-table-scroll`, and `panel-build` never scrolls sideways. |
| B13 save row | every width | The save row does not wrap; the link field shrinks to fit (min 8rem). |
| B14 browser zoom | zoom makes the CSS viewport < 1200 | Same as B2; there is no separate rule. |

Failure, cancel and repeat cases do not apply: these are static layout rules with no state machine. The
removed tab state had them; nothing replaces it.

## Data flow

No data crosses modules differently. The page passes `build` and `results` nodes to `WorkbenchColumns`;
nothing else about layout is computed in JavaScript.

## Defaults

- Two columns become unconditional and the tabs are removed (follows OD1 = 1200); alternative given up: keeping tabs between a lower minimum and 1200, which keeps two layouts.
- The `build-editor` container queries are folded into the base rules (compact editor everywhere), not deleted outright; deleting them would switch desktop users to the larger editor that today shows only at 768–1199.
- The gutter's finished-time span stays in the DOM, hidden by `.gutterEndTime`; alternative given up: stop rendering it, which rewrites `aoe4-compact-view` and `aoe4-step-annotations` cases that read its text.
- `workbench-tabs.tsx` is renamed `workbench-columns.tsx` exporting `WorkbenchColumns`; alternative given up: keep the tab name on a component with no tabs.
- Test ids `workbench-split`, `build-column`, `results-column`, `panel-build`, `panel-results` and helper names `SPLIT_VIEWPORT`, `WIDE_VIEWPORT` keep their names; alternative given up: renaming to "desktop" names across about 25 spec files.
- `showTab` is deleted with its call sites; alternative given up: keeping it as a panel-visible assertion.
- The width floor sits on `.pageSection`, not `body`, so the site header and other apps are untouched; `pages/_app.js`'s viewport meta stays (other apps keep phone support).
- The two surviving `aoe4-narrow-layout` cases move to the topic specs (`inline-issues`, `pin-compare`) rather than a renamed file.
- Specs written test-first (delivery step 1) so each PR stays green on its own.

## Owner decisions

Decided 2026-11-16 (Q109, Q110, Q111): OD1 = 1200 px, OD2 = A (sideways scroll only; C8/B8 notice dropped), design and defaults approved.

**OD1. Minimum supported width.** Decided: **1200 px.**

| option | for | against |
|--------|-----|---------|
| 1200 (recommended) | The width the two-column layout already starts at; every desktop rule (two columns, one-line save row, compact editor) is already built and tested there; the 1280x800 and 1280x720 test viewports sit above it; covers 1280, 1366, 1440, 1536 and 1920 px laptops and desktops. | A 1280 px laptop at 125% browser or OS zoom (1024 CSS px) and iPad landscape (1024–1180) scroll sideways. |
| 1024 | Those zoomed laptops and tablets fit. | Two columns at 1024 are about 444 px each, never built or tested: the save row would need to wrap again or be redesigned, the step table scrolls more. New layout work in a removal milestone. |
| 1280 | Equals the test viewport. | Drops 1200–1279, which works today, for no gain. |

**OD2. Below the minimum width.** Decided: **A, sideways scroll only.**

| option | behavior | for | against |
|--------|----------|-----|---------|
| A (recommended) | B2: the 1200 px layout, scrolled sideways; pinch-zoom out on a phone shows it whole. | No breakpoint at all in the AoE4 CSS; nothing to maintain; one spec. | A phone visitor gets no explanation. |
| B | A plus C8/B8: a one-line notice above the heading, shown only below 1200 px. | Phone visitors learn why the page is wide. | One media query and one more spec case; notice text to maintain. |
| (not offered) notice only, no width floor | The two columns squeeze into 390 px. | | Fails M10.2 ("nothing breaks or overlaps at 390 px") unless a narrow layout is kept, which is what M10 removes. |
