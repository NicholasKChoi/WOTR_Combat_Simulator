## Context

Today the step table shows a build's steps but not how the run went, and the charts dim only on `invalid`, `rejected` or `failed`. This ticket adds a first column to every step-table row that shows the live step's kind and, when the step aligns to a step of the shown run, its started, finished, waited and blocked-by text; it dims the run cells and the charts together whenever the shown result no longer describes the live input (M7.4); and it makes the table fit its split-layout column so the new column does not push the row controls out of view. The step timeline stays in this ticket (the next one deletes it).

## Acceptance criteria

- [ ] On Table view after a run, every `step-row` has `data-kind`; `step-started` equals `formatStepTime` of the API response's `steps[i].startedAt` for the same text (cross-checked with `simulateOk` on that text), and `step-finished` equals `ongoing` for an `in-progress` step and `formatStepTime(completedAt)` otherwise; `step-kind-legend` is visible and has one `[data-kind]` item per kind whose `STEP_KINDS` label is not null, and there is exactly one `step-kind-legend` on the page.
- [ ] Kind colour on screen: the computed `border-left-color` of a row's `step-run` equals that of the `step-kind-legend` item with the same `data-kind`, and the run asserts at least two different kinds with different colours; `step-kind-badge` is absent exactly on rows whose `data-kind` is `other`.
- [ ] A `not-reached` row's `step-started` and `step-finished` read an en dash and its `step-blocked-by` reads `not reached (<waitingOn>)` (waitingOn from the API response); a `completed` row with `waitSeconds === 0` has an empty `step-blocked-by`; `data-long-wait="true"` is set on exactly the rows whose API `waitSeconds >= 60` (asserting first that at least one row is long and at least one is not); a flagged row's `step-run` has a computed `background-color` different from an unflagged row's.
- [ ] Unit table (`step-annotation.test.ts`, `renderToStaticMarkup` of `StepRunCell` and the table, following `issue-list.test.ts`): one row per case of `completed`, `in-progress` (Finished reads `ongoing`), `waiting` (Blocked by ends with `still waiting on <waitingOn>`, alone when the breakdown is empty), `not-reached`, and `run: null` (no `step-started`, no `data-status`).
