## Context

The page has no help, and the step-kind legend is repeated above both editor views (M11.6). This ticket adds a native `<dialog>` opened from a button beside the page title, and moves `StepKindLegend` into it. It depends on the wait-text, unit-line and upgrade-dot, and zoom tickets so that it lands last: sections 4 and 5 of B-H6 describe the wait text, the marker control, unit lines and upgrade dots, and zoom, pan and reset as live features of the page, in the design's wording, with no "not yet shipped" caveat. Nothing in this ticket is a stopgap that a later ticket brings up to date; the docs ticket only documents.

## Scope

All paths under `components/apps/aoe4-build-order/` unless noted. Read at the end state of the Depends-on tickets: the charts are one table with one `MarkerControl` (`chart-marker-legend`, heading `Markers`, C9), each chart has its own zoom bar while zoomed (`chart-zoom-pan-earlier` `Show earlier in <title> chart`, `chart-zoom-pan-later` `Show later in <title> chart`, `chart-zoom-reset` visible text `Reset zoom`, C12), the Units chart draws one line per unit line with upgrade dots (`chart-upgrade-dot` filled for the current run, `chart-pinned-upgrade-dot` dashed rings for the pinned run), and a step annotation's Blocked by text names what it waited for and, for a step still waiting, ends in `still waiting for <what>` (SGS-193). Use the design's names exactly.

- New `page-help.tsx` (C18): `PageHelp()` renders `button[data-testid=help-open]` (visible text `How this page works`, `aria-haspopup="dialog"`) and `dialog[data-testid=help-modal]` with `aria-labelledby` pointing at its `h2` `How this page works`, a `button[data-testid=help-close]` (accessible name `Close`) first in the dialog, then the seven sections of B-H6 in order. Each section is a `section[data-testid=help-section]` with `aria-labelledby` pointing at its own `h3` inside it; tests address a section by its position among the `help-section` elements (the fourth is section 4), never by heading text. Contents: 1 the two columns and the run bar; 2 the editor views (text with gutter annotations, table with run cells); 3 step kinds, as `StepKindLegend` (`step-kind-legend`); 4 what the yellow tint means, with a `help-warn-tint` swatch (the step is still waiting, was never reached, or waited 60 s or longer), and what Blocked by lists (each wait with its time, then, for a step still waiting, what it is still waiting for; a step never reached shows the not-reached form); 5 charts: series legend toggles, dashed = pinned, the marker control, unit lines and upgrade dots (filled for the current run, dashed rings for the pinned run), zoom, pan and reset, the drag handle and the caret; 6 pin and compare; 7 save and links. Sections 4 and 5 state these features as present behavior. Wording and the order of sentences inside a section are the implementer's; each control is named the way the page names it (its visible text, or its accessible name without the chart title or marker kind it carries), read from the live page, not retyped from memory.
- `help-warn-tint` gets its background from the same `.warn` class a tinted run cell uses (`step-annotation.module.css`, applied through `annotationToneClass` in `step-annotation.tsx` or by importing that module's class); no colour value is copied into `page-help.module.css`. If the `.warn` rule's selector only matches the run cell's `td` with the needed specificity, the swatch's element or selector is chosen so the computed background matches.
- Open and close behaviour: `help-open` calls `showModal()`; the content scrolls to its top on every open; `help-close` and Escape (native) close it; a click whose target is the dialog element and whose coordinates lie outside the dialog's `getBoundingClientRect()` (the backdrop) closes it, while any click inside that rect, including on the dialog's own padding, does not (B-H2 "outside the dialog's box"). Focus returns to `help-open` on close. No state is kept between opens.
- New `page-help.module.css`: dialog max height about 80% of the viewport with its content scrolling inside it, the swatch's size, the heading row styles if they are local to the component. `workbench.module.css`: the heading row (`h1` then `help-open` on one line inside `.pageSection`).
- `pages/apps/aoe4-build-order.tsx`: the `h1` and `PageHelp` in a heading row inside `.pageSection`, before the run bar (`BuildInput`) in DOM order, so `help-open` comes before the run bar in Tab order. `help-open` is always enabled in every page state; the modal content is static and starts no run.
- Remove the legend from the page (B-H7): `build-text-editor.tsx` and `step-table.tsx` stop rendering `StepKindLegend` (and drop its import); `step-annotation.tsx` keeps exporting `StepKindLegend`, now used only by `PageHelp`. `chart-pinned-legend`, `MarkerControl`, `chart-reorder-help`, `copy-saved-link-hint` and every message stay.
- The dialog, with the legend inside it, is in the DOM in every page state (B-H9), and Playwright's `getByTestId` and `getByText` match hidden nodes. So after this ticket the page holds exactly one `step-kind-legend`, inside `help-modal`, whatever the result, steps or errors, and "the legend is absent" is expressed as "no `step-kind-legend` outside `help-modal`" (for example `page.locator('[data-testid="step-kind-legend"]:not([data-testid="help-modal"] *)')` has count 0). Rule for existing tests that read the legend (found by searching `step-kind-legend`, `StepKindLegend` and `legendColors`; examples, search again before editing: `step-annotation.test.ts` "renders no run cell, legend or kind without annotations" and "keeps the start row cell empty and shows the legend"; `acceptance/aoe4-compact-view.spec.ts` (its `legend(page)` counts, including the count-0 checks before a result and for `START_ONLY_BUILD`, the legend-above-textarea layout read, and the "legend follows the parsed steps" half of its title); `acceptance/aoe4-step-annotations.spec.ts` (the one-legend count and `legendColors`); `acceptance/aoe4-results-split.spec.ts` (the count-0 check in "a build with no steps ..."); `acceptance/aoe4-build-order-knight-longbow-page.spec.ts` (its `toBeVisible` on the legend)):
  - an assertion that the legend shows (visible, count 1, above the editor or table) is dropped or rewritten to the open modal;
  - an assertion that the legend is absent (count 0, `not.toContain`) is rewritten to the outside-modal check above, or dropped where the case it guarded (no result, no steps) no longer changes the legend; the rule that the legend follows the parsed steps is gone, and the test title loses that half;
  - in `step-annotation.test.ts` the table rendered with annotations asserts it contains no `step-kind-legend` (so it fails if the table still renders it), and the without-annotations test drops its legend half;
  - an assertion about run-cell colours keeps its expected values and reads the legend colours from the legend inside the open modal.
  The implementer lists every test edited.
- The modal's static text and markup are in the DOM in every state (respec 2). Existing specs that read a page-wide locator or `querySelectorAll` count, set or size comparison (`getByText`, `locator('h3')`, `querySelectorAll`) keep their expected values: the implementer searches `acceptance/` for them and either scopes that locator to exclude `help-modal` without changing its expected value, or picks markup and text that none matches. Examples found at base: `aoe4-split-scroll.spec.ts` "the headings share a size and lead their panels" counts `getByText('Build order', { exact: true })` as 1, so no section heading may be exactly `Build order`; the same test builds `charts` as the set of font sizes of every page-wide `h3` and asserts `toHaveLength(1)`, and the seven `h3` section headings in `help-modal` would join that set, so that query is scoped to exclude `help-modal` (the modal headings are not restyled to match the chart headings).
- New `page-help.test.ts` (`renderToStaticMarkup`, no DOM): the dialog is in the markup without an `open` attribute (B-H9), `help-close` comes first in the dialog, there are seven `help-section` elements each labelled by an `h3` inside it, the third holds `step-kind-legend` with the six labelled kinds (the labels `StepKindLegend` gives) and the fourth holds `help-warn-tint`.
- New `acceptance/aoe4-help-modal.spec.ts` (B-H1 to B-H9), shared setup from `acceptance/helpers.ts` (`openPage`, `waitForRun`, `plotPoint`, `readLayout`, viewports; no local copy of a chart helper), layout comparisons read in one `evaluate` under `expect.poll` or `toPass` (LESSONS, exemplar `aoe4-chart-views.spec.ts`). Text checks on a section compare case-insensitively against that section's `textContent`.
- Docs: `docs/aoe4-build-order-ui.md` says the kind legend renders above the text editor and the step table, and has no help modal section; the M11 docs ticket rewrites those statements (its search list names the "kind legend renders above" sentence), so this ticket edits no doc.

**Out of scope:** any chart, marker, zoom, unit-line or wait-text behavior (their own tickets; this ticket only describes them); engine and API; docs (the docs ticket); a "briefly incomplete" caveat or a follow-up ticket for the help content; storing anything about the modal; the pinned legend, marker control and reorder help text.

## Acceptance criteria

- [ ] Open (B-H1) (respec 1): click, Enter and Space on `help-open` each open `help-modal` (it is visible, and the page behind it does not take clicks or Tab focus); focus is on `help-close`; with the content scrolled down, closing and opening again shows it at scroll top 0. At a viewport short enough that the content is taller than the dialog (the spec asserts the content's `scrollHeight` exceeds its `clientHeight` first), the dialog's height is at most 0.8 x `innerHeight` + 1 px and its content scrolls inside it (read in one `evaluate`). Opening sends no simulate request and changes no text, build selection, run status or chart state (the spec counts requests and reads that state before and after).
- [ ] Close (B-H2) (respec 1): `help-close`, Escape, and a click on the backdrop (a point outside the dialog's rect) each close it and put focus on `help-open`; a click on text inside the content and a click on a point just inside the dialog's rect edge (on its padding) leave it open. A test fails if a click inside the dialog's box closes it.
- [ ] Repeat (B-H3): opening it twice shows the same content, and a state changed inside it in the first open (scroll position) is not kept.
- [ ] Keyboard (B-H4): with it open, Tab and Shift+Tab only ever land on elements inside the dialog and wrap within it.
- [ ] Availability (B-H5): `help-open` is enabled, and opens a modal with seven `help-section` elements and the same heading texts, with no result, with invalid text (a syntax error shown), and while a run is loading.
- [ ] Sections (B-H6) (respec 1): the dialog holds seven `help-section` elements, each labelled by an `h3` inside it. The third holds `step-kind-legend` with the six labelled kinds; the legend colours equal the border colours of the run cells of the same kinds on a table view with a result (read from the page, legend read inside the open modal).
- [ ] Section 4 (live features) (respec 1): `help-warn-tint` shows the same computed background as a run cell tinted for a still-waiting step (the spec builds a waiting step, asserts from the API that it is `waiting`, and compares computed backgrounds). The spec first asserts a live `step-blocked-by` on the page starts its waiting tail with `still waiting for`, then asserts the fourth `help-section`'s text contains `still waiting for`, `waiting`, `never reached` or `not reached`, `60`, and `Blocked by`.
- [ ] Section 5 (live features, no caveat) (respec 1): on the Knight/Longbow template with a pinned run and one chart zoomed, the spec runs a feature table. Each row first asserts the feature is on the live page and reads its term from it, then asserts the fifth `help-section`'s text contains the term: the series legend's heading text (`chart-series-legend`); the word `dashed` with `chart-pinned-legend` present; the marker control's heading text (`chart-marker-legend`); `chart-zoom-reset`'s visible text; the pan buttons' accessible names with the trailing ` in <title> chart` removed (the spec asserts that form first); the drag handle's and the caret's accessible names with the chart title and one adjacent space removed (respec 2) (`chart-drag-handle`, `chart-collapse`; the spec asserts the full name equals `<verb> <title> chart` first, then the term is the name without the title, such as `Reorder chart` and `Collapse chart`; the caret's verb is read from the live state, and the section must contain the word `collapse` or `expand` for the state seen; alternatively every row compares whitespace-normalized and case-insensitively, and the spec says so); `upgrade dot` with `chart-upgrade-dot` and `chart-pinned-upgrade-dot` both present; `unit line`. A test fails if a row's term is missing from the section. The modal's text matches none of `/coming soon|not yet (available|supported|shipped)|incomplete|unavailable/i`.
- [ ] Absorbed legend (B-H7) (respec 1): the page holds exactly one `step-kind-legend`, inside `help-modal`, and none outside it, in the text view and the table view, before a result, with a result, with a build with no steps, and with a syntax error shown. `chart-pinned-legend` (with a pinned run), the marker control, `chart-reorder-help`, `copy-saved-link-hint` and the page's messages are still there. A test fails if either editor view still renders the legend (a unit render of `StepTable` with annotations contains no `step-kind-legend`, and the spec's outside-modal check).
- [ ] Placement (B-H8) (respec 1): at `MIN_SUPPORTED_VIEWPORT` and `WIDE_VIEWPORT`, `help-open` is inside `.pageSection`, its vertical centre lies between the `h1`'s top and bottom, and its left edge is at or right of the `h1`'s right edge (all rects read in one `evaluate` under `toPass`); below 1200 px it scrolls sideways with the page; in DOM order `help-open` comes before the run bar's controls, and in Tab order from the top of the page `help-open` is reached before the build select (the spec states which earlier stop, if any, the layout puts first).
- [ ] Server render (B-H9): the HTML of the page before hydration holds `help-modal` closed, with no `open` attribute (a unit assertion on the render, and the spec's check before it clicks anything that the dialog is not shown).
- [ ] `page-help.test.ts` (respec 1) covers closed dialog markup, seven `help-section` elements each labelled by an inner `h3`, the six legend labels in the third and `help-warn-tint` in the fourth, and fails if `help-close` is not first in the dialog.
- [ ] Existing tests (respec 1): every test that asserted the legend above the editor or table, or a page-wide legend count, is dropped or rewritten to the open modal or to the outside-modal check, the run-cell colour assertions keep their expected values, every existing page-wide locator or `querySelectorAll` count, set or size comparison keeps its expected value (respec 2), and the report lists each test edited.
- [ ] No INVARIANTS.md regressions
