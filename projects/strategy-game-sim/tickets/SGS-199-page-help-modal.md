- **Milestone**: M11
- **Priority**: medium
- **Risk**: low

## Context

The page has no help, and the step-kind legend is repeated above both editor views (M11.6). This ticket adds a native `<dialog>` opened from a button beside the page title, and moves `StepKindLegend` into it. It depends on the wait-text, unit-line and upgrade-dot, and zoom tickets so that it lands last: sections 4 and 5 of B-H6 describe the wait text, the marker control, unit lines and upgrade dots, and zoom, pan and reset as live features of the page, in the design's wording, with no "not yet shipped" caveat. Nothing in this ticket is a stopgap that a later ticket brings up to date; the docs ticket only documents.

## Scope

All paths under `components/apps/aoe4-build-order/` unless noted. Read at the end state of the Depends-on tickets: the charts are one table with one `MarkerControl`, each chart has its own zoom bar and Reset while zoomed, the Units chart draws one line per unit line with upgrade dots (filled for the current run, dashed rings for the pinned run), and a step annotation's Blocked by text names what it waited for (for example `still waiting for Castle Age`, `a free <building> 0:23`). Use the design's names exactly.

- New `page-help.tsx` (C18): `PageHelp()` renders `button[data-testid=help-open]` (visible text `How this page works`, `aria-haspopup="dialog"`) and `dialog[data-testid=help-modal]` with `aria-labelledby` pointing at its `h2` `How this page works`, a `button[data-testid=help-close]` (accessible name `Close`) first in the dialog, then the seven sections of B-H6 in order, each under its own heading: 1 the two columns and the run bar; 2 the editor views (text with gutter annotations, table with run cells); 3 step kinds, as `StepKindLegend` (`step-kind-legend`); 4 what the yellow tint means, with a `help-warn-tint` swatch carrying the same `.warn` background as a tinted run cell (the step is still waiting, was never reached, or waited 60 s or longer), and what Blocked by lists (each wait with its time, then, for a step still waiting, what it is still waiting for; a step never reached shows the not-reached form); 5 charts: series legend toggles, dashed = pinned, the marker control, unit lines and upgrade dots (filled for the current run, dashed rings for the pinned run), zoom, pan and reset, the drag handle and the caret; 6 pin and compare; 7 save and links. Sections 4 and 5 state these features as present behavior. Wording and the order of sentences inside a section are the implementer's; each feature is named the way the page names it (control labels and accessible names are read from the live page, not retyped from memory). The component opens with `showModal()` from the button, scrolls the content to its top on every open, closes on `help-close`, Escape (native) and a click on the backdrop (a click inside the content does not close it), returns focus to `help-open` on close, and keeps no state between opens.
- New `page-help.module.css`: dialog max height about 80% of the viewport with its content scrolling inside it, the swatch, the heading row styles if they are local to the component. `workbench.module.css`: the heading row (`h1` then `help-open` on one line inside `.pageSection`).
- `pages/apps/aoe4-build-order.tsx`: the `h1` and `PageHelp` in a heading row inside `.pageSection`, before the run bar (`BuildInput`) in DOM order, so `help-open` is first in Tab order. `help-open` is always enabled in every page state; the modal content is static and starts no run.
- Remove the legend from the page (B-H7): `build-text-editor.tsx` and `step-table.tsx` stop rendering `StepKindLegend` (and drop its import); `step-annotation.tsx` keeps exporting `StepKindLegend`, now used only by `PageHelp`. `chart-pinned-legend`, `MarkerControl`, `chart-reorder-help`, `copy-saved-link-hint` and every message stay.
- Tests that assert the legend on the page (found by searching `step-kind-legend` and `StepKindLegend`; examples, search again before editing): `step-annotation.test.ts` ("renders no run cell, legend or kind without annotations" and "keeps the start row cell empty and shows the legend": the table no longer renders the legend, so these assert its absence or lose the legend half); `acceptance/aoe4-compact-view.spec.ts` (its legend counts and the legend-above-textarea layout read), `acceptance/aoe4-step-annotations.spec.ts` (the one-legend count and the `legendColors` helper, which now read the legend inside `help-modal` after opening it), `acceptance/aoe4-results-split.spec.ts` (a `step-kind-legend` count of 0 stays true while the modal is closed, so keep it only with that meaning), `acceptance/aoe4-build-order-knight-longbow-page.spec.ts` (its `toBeVisible` on the legend). Rule: an assertion that the legend shows above the editor or table is dropped or rewritten to the modal; an assertion about run-cell colours keeps its expected values and reads the legend colours from the open modal. The implementer lists every test edited.
- New `page-help.test.ts` (`renderToStaticMarkup`, no DOM): the dialog is in the markup without an `open` attribute (B-H9), `help-close` comes first in the dialog, the `step-kind-legend` renders with the six labelled kinds (the same labels `StepKindLegend` gives), the seven sections are present in order, and `help-warn-tint` is present.
- New `acceptance/aoe4-help-modal.spec.ts` (B-H1 to B-H9), shared setup from `acceptance/helpers.ts` (`openPage`, `waitForRun`, `plotPoint`, `readLayout`, viewports; no local copy of a chart helper), layout comparisons read in one `evaluate` under `expect.poll` or `toPass` (LESSONS, exemplar `aoe4-chart-views.spec.ts`).
- Docs: `docs/aoe4-build-order-ui.md` says the kind legend renders above the text editor and the step table, and has no help modal section; the M11 docs ticket rewrites those statements (its search list names the "kind legend renders above" sentence), so this ticket edits no doc.

**Out of scope:** any chart, marker, zoom, unit-line or wait-text behavior (their own tickets; this ticket only describes them); engine and API; docs (the docs ticket); a "briefly incomplete" caveat or a follow-up ticket for the help content; storing anything about the modal; the pinned legend, marker control and reorder help text.

## Acceptance criteria

- [ ] Open (B-H1): click, Enter and Space on `help-open` each open `help-modal` (it is visible, and the page behind it does not take clicks or Tab focus); focus is on `help-close`; with the content scrolled down, closing and opening again shows it from its top; the dialog's height is at most about 80% of the viewport and its content scrolls inside it at a short viewport. Opening sends no simulate request and changes no text, build selection, run status or chart state (the spec counts requests and reads that state before and after).
- [ ] Close (B-H2): `help-close`, Escape, and a click on the backdrop each close it and put focus on `help-open`; a click on text inside the content leaves it open. A test fails if a click inside the content closes it.
- [ ] Repeat (B-H3): opening it twice shows the same content, and a state changed inside it in the first open (scroll position) is not kept.
- [ ] Keyboard (B-H4): with it open, Tab and Shift+Tab only ever land on elements inside the dialog and wrap within it.
- [ ] Availability (B-H5): `help-open` is enabled, and opens a modal with the same section headings, with no result, with invalid text (a syntax error shown), and while a run is loading.
- [ ] Sections (B-H6): the dialog's section headings are seven, in the order of Scope. Section 3 holds `step-kind-legend` with the six labelled kinds; the legend colours equal the border colours of the run cells of the same kinds on a table view with a result (read from the page).
- [ ] Section 4 (live features): `help-warn-tint` shows the same background as a run cell tinted for a still-waiting step (the spec builds a waiting step, asserts from the API that it is `waiting`, and compares computed backgrounds); the section names the three causes of the tint and says what Blocked by lists, including that a waiting step names what it is still waiting for; with a step whose `step-blocked-by` reads `still waiting for ...` on the page, the section describes that form.
- [ ] Section 5 (live features, no caveat): the section names the series legend toggles, dashed = pinned, the marker control, unit lines, upgrade dots (filled for the current run, dashed rings for the pinned run), zoom, pan and reset, the drag handle and the caret. For every feature the page offers that the spec can reach (the marker control's accessible name, the zoom bar's pan and reset names after a chart is zoomed, `chart-upgrade-dot` and `chart-pinned-upgrade-dot` present on the Knight/Longbow template with a pinned run), the spec reads its name or testid from the live page first, then asserts the section mentions it; a test fails if the section describes a feature the page does not have or omits one it has. The modal carries no sentence saying a feature is coming, incomplete or not yet available.
- [ ] Absorbed legend (B-H7): with the modal closed, `step-kind-legend` is on the page in neither the text view nor the table view, with or without a result and with a syntax error shown; it is present only inside `help-modal`. `chart-pinned-legend` (with a pinned run), the marker control, `chart-reorder-help`, `copy-saved-link-hint` and the page's messages are still there. A test fails if either editor view still renders the legend.
- [ ] Placement (B-H8): `help-open` is on the same line as the `h1` and to its right, inside `.pageSection` (rects read in one evaluate), at `MIN_SUPPORTED_VIEWPORT` and `WIDE_VIEWPORT`; below 1200 px it scrolls sideways with the page; in DOM order and Tab order it comes before the run bar's controls (the first Tab stop on the page after load is `help-open`, or the spec states which earlier stop the layout puts first and asserts `help-open` precedes the build select).
- [ ] Server render (B-H9): the HTML of the page before hydration holds `help-modal` closed, with no `open` attribute (a unit assertion on the render, and the spec's check before it clicks anything that the dialog is not shown).
- [ ] `page-help.test.ts` covers closed dialog markup, the six legend labels, the seven sections in order and `help-warn-tint`, and fails if `help-close` is not first in the dialog.
- [ ] Every test that asserted the legend above the editor or table is dropped or rewritten to the modal, the run-cell colour assertions keep their expected values, and the report lists each test edited.
- [ ] No INVARIANTS.md regressions
