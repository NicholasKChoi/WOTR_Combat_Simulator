## Non-blocking notes

- Commit 55ed3a1 on `sgs-114-chart-layout` has the subject "SGS-114: re-indent chart body fragment", which puts a ticket id in a shipped commit message. It does not matter on a squash merge with the PR title, but the implementer and rework prompts should drop the id prefix.
- In SGS-114, the Per villager checkbox (`headerControls`) has moved from the title row into the collapsible body. That is intended and documented, but anyone with a layout spec that looked for it in the title row will see it under the title now.
- In SGS-123, `readMyBuilds` removes the whole storage key when the stored value fails to parse. Under design C5 that is correct, but once wired, a corrupt value deletes every stored edit secret with no recovery. When the page wiring ticket lands, consider whether it should log or keep a backup copy.
- `useChartLayout.move/toggle` compute the next layout from the render-time `layout` closure, not a functional updater. Two activations within one render would lose one. That cannot happen with button clicks today.
- The known acceptance failure at `acceptance/aoe4-build-order-pin-compare.spec.ts:141` was already failing at 086951e, so this stack did not cause it (SGS-126 will fix it).
