## Gaps

1. **Scope, annotation inner span font** - Scope says the inner `span` (0.8rem today in `.annotations li > span`) "must follow the compact font rule" but does not say how. 0.8rem is a fixed rem, so it does not follow `--editor-font-size`. The implementer must guess a value (0.8em of the compact font? 0.8rem kept?), and that value decides whether `m:ss` and `ongoing` fit in the 8ch column. Fix: state the rule, e.g. "the span's font size is a fixed fraction (0.8) of `--editor-font-size` in both modes, so at 1rem it still computes to today's 0.8rem (M8 layout unchanged at 48rem and wider); the widest gutter text (`ongoing`, or the longest `m:ss`) is not clipped in the 8ch column". Without the ratio rule, criterion 3 ("annotation column and font keep their M8 values") is also unverifiable for the span.
2. **Acceptance criterion 8 (and the second half of 7)** - "any other test pins nothing new in its setup" has no observable outcome and is not checkable. Fix: replace it with "no existing test is edited except to change its viewport or the setup it reads layout from; the implementer lists each edited file and the reason. A test that reads annotation text uses `toHaveText` or `textContent` and keeps its expected value." (I found no existing test asserting `toBeVisible` on gutter `step-finished`; the readers in `aoe4-compact-view.spec.ts` and `aoe4-step-annotations.spec.ts` use `toHaveText`, which still passes on a hidden node.)

## Notes (non-blocking)

- Criterion 2 is tight. At 1280x800 the editor is about 562 px; at 0.875rem monospace 48 chars is about 403 px; the textarea content width then comes out near 407 px (562 minus a 48 px min-width gutter plus 8 px padding, minus an 8ch annotation column, minus textarea padding and border). The margin is a few pixels. Scope already allows narrowing the gutter `min-width` and annotation padding in compact mode and requires recording measured widths, which is enough. The author may want to say that the bound, not the C14 values, is the controlling rule.
- A `@container` query cannot style the container itself, so `--editor-font-size` must be set on `.gutter`, `.annotations` and `.textarea` inside the compact rule, not on `.editor`. Scope's wording ("sets `--editor-font-size` ... for the gutter, annotations and textarea together") is compatible; worth one clause.
- The textarea also carries Bootstrap `form-control font-monospace`; `.form-control` sets `font-size: 1rem`. Today `.textarea` ties on specificity and wins by CSS order. Criterion 2 would catch a loss, but the implementer should check the computed font size of the textarea.
- `step-finished` is a `data-testid`, not a class. Scope's "selector scoped to the annotation column" is fine, but the implementer needs a class in `step-annotation.module.css` or a container-scoped attribute selector. Scope already allows touching `step-annotation.tsx`. No testid exists on the `.editor` wrapper, so Scope's "only if" hook for `build-text-editor.tsx` is in fact required for the width criteria 1 and 2.
- Design C14 uses `(max-width: 47.99rem)`; the ticket says "below 48rem". Either is fine; the range form `(width < 48rem)` is cleaner.
