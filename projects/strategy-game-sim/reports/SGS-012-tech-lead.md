## Blocker

- `package.json:8-10` - production runtime / open question answered unilaterally
  - What: `"engines": { "node": ">=22.12.0" }` makes Vercel ignore the project's Node 24.x setting. Preview build log (deployment 6QcYLshqg6kqY7f4hVnK1pm1BZ9X): "Due to "engines": { "node": ">=22.12.0" } ... the Node.js Version defined in your Project Settings ("24.x") will not apply, Node.js Version "26.x" will be used instead". It also says the range "will automatically upgrade when a new major Node.js Version is released".
  - Why a human must decide: the ticket (respec 1) and its acceptance criterion "Vercel check green, building on Node 24.x" assume production stays on 24.x. Instead the merge moves every page and `/api/fight` to Node 26.x, and every later Node major will move production again with no change in the repo. None of the gates ran on 26.x: suite, review, acceptance and implementer all used Node v22.17.0. The Vercel check is green, but the build passing says nothing about runtime behavior on 26.x. Choosing which Node range production should run is an owner call that the ticket got wrong.
  - Direction: bound the range so the project setting applies again, for example `"node": "^22.12 || ^24"` or `"24.x"`. Rerun the Vercel check and confirm the log shows 24.x with no override warning. The other option is for the owner to accept 26.x and its auto-upgrade, and then have acceptance re-run on Node 26. Either way, update the ticket criterion and the PR Summary to match.
