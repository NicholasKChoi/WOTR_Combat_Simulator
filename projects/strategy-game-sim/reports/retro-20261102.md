## Patterns

### P1. User-visible UX defects escape every local gate (repeat: M2 Y-axis overlap, M4 E2E findings 1-6)

Evidence:
- The E2E table above (BACKLOG 311128c).
- `reports/retro-20261101.md` "Not acted on": owner-found Y-axis overlap.
- SGS-066 review 1 (247px bar measured at 390px, judged only as a scroll-margin problem).
- SGS-073 review (overflow-only width sweep).
- SGS-067 and SGS-074 criteria (attribute-only).

Root cause / escape point:
- Spec gap at the designer. The design never states, for the UI:
  - the visible effect of a state;
  - the final user-facing string;
  - what an invalid-state control does;
  - the keyboard pattern of a role;
  - a size budget for sticky elements.
- Designer "Left to tickets" includes "styling, wording", so these fall through.
- Secondary escape at acceptance-test and review: a state marked by an attribute is asserted only by the attribute, and screenshots are never looked at.

Proposal 1 (engine): `/home/choin/git/code-factory/agents/designer.md`, section "Check before reporting". Add:

```diff
+- For each UI surface: the visible effect of every state attribute or class the design names
+  (what changes on screen, not only that the attribute is set); every user-facing message exactly
+  as the user reads it on that surface (no internal field names, no doubled spaces from joined
+  parts); what each control does when activated in an invalid or empty state; the keyboard
+  behavior of every ARIA widget role used (tablist: arrow keys, Home/End); and the maximum height
+  of any sticky or fixed element at the narrowest supported width.
```

And in "Left to tickets", narrow the wording:

```diff
-internals, styling, wording
+internals, and styling or wording that does not change what a user sees or reads (user-visible
+states and messages are design decisions and are fixed above)
```

Proposal 2 (engine): `/home/choin/git/code-factory/agents/acceptance-test.md`, section "Write". Add:

```diff
+- When a criterion names a visual state through an attribute or class (`data-error`, `aria-selected`,
+  `is-active`), also assert one computed style (`toHaveCSS`) that differs from the same element in
+  the default state; the attribute alone passes with no CSS.
```

Proposal 3 (repo): `/home/choin/git/WOTR_Combat_Simulator/.claude/code-factory/REPO.md`, section "### AoE4 build order" review checklist. Add:

```diff
+- For UI changes, take screenshots of each touched state at 360x760, 768 and 1280 and look at them:
+  a highlight attribute must change something visible; sticky or fixed elements must leave at
+  least 60% of a 360x760 viewport for content; user-facing messages read as plain sentences.
```
