## Design deviations and notes for review

- `buildStoreFromEnv(env?: NodeJS.ProcessEnv)` uses an optional parameter (design C2 signature) rather than the ticket's `env = process.env` default, since a default cannot tell the no-argument call apart for memoization. Behavior matches the ticket text.
- The window rule ("same window: stored + 1, else 1") appears twice: `nextCounter` in `build-store.ts` (memory and file stores) and one inline expression in `blob-build-store.ts`'s `bumpCounter`. `build-store.ts` must export exactly the listed names and `saved-builds.ts` must not change, so there is no allowed shared home. A reviewer applying the "copied helper is blocking" checklist rule should treat this as a spec question, not a silent copy.
- The file store's path check is stricter than "inside `<dir>`": a key must also equal its own normalized relative path, so `development/rate-limit/../builds/X.json` (a client key landing on a build file) throws. This is what makes the ticket's `../x` row throw at all (`development/rate-limit/../x.json` resolves inside `<dir>`).
- Blob `putBuild` and the counter `put` set `contentType: 'application/json'` and `addRandomSuffix: false` on the counter write too (not required by the ticket; keeps the key stable).
