## Summary
Three bits of AoE4 workbench UI state got lost or stuck. This keeps them.

- **Step-table open rows follow their step.** The page now holds one "More options" open flag per step row, so the flags outlive the table. Moving a row swaps the two rows' flags, deleting a row removes its flag, an added row starts closed unless its default step sets an optional field, and changing a row's action closes it. Other table edits leave every flag alone. An edit made in the textarea or by picking a prebuilt build keeps one flag per parsed step: a row stays open if it was open or now sets an optional field, and flags past the last step are dropped. Text that does not parse leaves the flags unchanged. Switching Text/Table, text going unparseable and back, and switching tabs no longer reset the flags.
- **Text/Table toggle disabled on Results.** While the Results tab is shown, both view buttons are disabled, so a click can no longer do something invisible. The active view keeps its fill and `aria-pressed`.
- **A failing stored pin gets dropped.** When the restore re-run on load gets back any response that is not ok (400 or 5xx), the stored pin is removed from `localStorage`. Before, only a 400 removed it, and a pin whose re-run always returned 5xx was re-POSTed on every load and could not be removed with Unpin. Only a request that fails outright (network) keeps the key. A Pin or Unpin made before the re-run finishes still wins.

Non-goals: the unsaved draft in a required number field (still lost on remount), chart resize while hidden, the dev Strict Mode double restore POST, saving the view or tab across reloads, and retrying a failed restore.

## Merge risk
**high** - a revert does not undo it: any non-ok restore response, including a transient 502/503/504, now permanently deletes the user's stored pin from `localStorage`.
