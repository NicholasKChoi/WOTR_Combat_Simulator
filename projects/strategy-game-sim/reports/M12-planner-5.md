## Design questions

Questions the ticket authors would hit. Rows 2 to 9 are settled here from the design or the code and go into the tickets as stated. Row 1 needs a designer or owner pick.

| # | outline(s) | question | why the design does not settle it |
|---|------------|----------|-----------------------------------|
| 1 | E | When another tab's storage write fires `storage` in this tab, should the selected `mine` entry take the re-read stored name even when this tab holds a newer name? Two cases: (a) this tab renamed but its storage write failed, then an unrelated write from another tab of this browser fires; (b) the build was renamed in another browser, this tab loaded the server name under D17, and the stored list still has the old name. **Recommended:** take the re-read name only when the re-read `MyBuildEntry.revision` is at least the selected entry's `loaded.revision`. `MyBuildEntry` already stores `revision`, so no new data is needed. | C12 says the selected entry "takes the re-read entry's name when the re-read list has it". Under D17 (server name wins on load) and the storage-failure rule (renamed in this tab only), that rule can put the stale stored name back on the label after an unrelated write. The design names neither case. It is a narrow edge (it needs a failed or out-of-date storage entry), so E can ship with the design's rule if the owner prefers. |
| 2 | A, D | Who bumps `info.version` to 2.7.0, given that both streams change `openapi.json`? | The design says "2.7.0" once and has two independent streams. **Settled:** both A and D set 2.7.0 and update the four pinned specs. The edits are identical, so the second to land rebases cleanly. No dependency is added. |
| 3 | A | What happens between A and C, when the API accepts `repeat` but the text form cannot print it? | Interim state the design does not discuss. **Settled:** acceptable. The page cannot enter `repeat` until C, and a save body with `repeat` gets the existing round-trip 400 (`reopening it as text would change the build`) until C. A's specs must not save a repeated build. |
| 4 | C | C3 says `x<repeat>` prints on every action "so an invalid repeat ... round-trips", but on `produce` it does not round-trip: with no `count` it re-reads as `count`, and with `count` it reads `x3 x2`, which is `syntax`. | A produce step carrying `repeat` never reaches the formatter: every save or load validates before formatting (`checkSaveBuildRequest`; stored builds passed it), and the table drops `repeat` on a change to produce. **Settled:** keep the design's printing rule. `parse-text.test.ts` round-trip rows cover build, move and research only and claim nothing for produce. |
| 5 | B | Which index does the identity alignment path (`live.text === shown.text`, which today returns `result.steps` indexes) use? | The design changes the length comparison but does not mention the identity path. **Settled:** it returns source indexes into `groupBySource(result.steps)`, the same as the `alignSteps` path. |
| 6 | B | What does "Blocked by" read on a combined row whose status is `not-reached`? C5 says "as `blockedByText` does today", which returns only `not reached (...)`. The page rules say it "ends with" that copy's text. | **Settled** by the page rule: the merged waits of the earlier copies, then that copy's `still waiting ...` or `not reached (...)` text. A single copy is unchanged. |
| 7 | B, C | When copy 2 is waiting on wood and copy 3 is not reached, the combined row shows `not reached (earlier-step)`, not the wood wait. | The design fixes this deterministically ("least advanced"; waitingOn from the first copy with that status). **Settled:** implement as written. The wood wait still appears in the copy list. Noted only so review does not bounce it. |
| 8 | E | Existing behavior contradicts D17: `aoe4-my-builds.spec.ts:302` asserts that the stored name wins, and UI doc line 348 says "one of My builds keeps its stored name". | **Settled** by the approved D17: E rewrites both to the server-name rule. |
| 9 | D | Existing tests use `PATCH` as the example disallowed method (`aoe4-named-builds-api.spec.ts:90`, `named-builds-routes.test.ts:246`). | **Settled:** D switches them to POST, with `Allow: GET, PUT, PATCH` (plus `DELETE` outside production). |
