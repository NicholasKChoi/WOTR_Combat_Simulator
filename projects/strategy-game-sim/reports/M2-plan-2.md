## What changed against the first plan

- **New K (doc update, docs-only).** `docs/aoe4-build-order.md` on main disagrees with design/M2.md at the lines
  the designer listed (verified on 68e004a: l.19-20, 53, 116-129, 163, 254, 257-263, 272-276, 280-309, 322-326).
  K is a wave-1 root so every ticket whose reviewer judges against the doc (E, M, F, G, I, J) can cite it.
- **New L (model.ts rally/start types).** main's `lib/aoe4-build-order/model.ts` lacks `BuildStart`,
  `BuildOrder.start?`, the `rally` action, and says "rally is required for villagers" on `produce`. The designer
  suggested folding this into the parse/validate outline; that outline now exceeds 400 lines (see E/M), so the
  types are a small wave-1 root instead. This lets parse (E) and validate (M) be siblings rather than a chain.
  The manager may fold L into K's PR if a 30-line type diff in a docs ticket is acceptable; the plan keeps K
  docs-only as asked.
- **Old E split into E (parse/format) and M (validate).** The rally/start grammar and seven new validation
  rules push the combined estimate to about 550 lines.
- **Old F split.** Rally state, the `rally` step, `start.villagers`/`start.rally` and the same-instant ordering
  rule add about 100 lines to the engine core. `build`, `move`, landmark age-ups and explicit-house supply move
  out of F into G, which already owned auto-houses (they share builder pull, walk legs and return). Depth is
  unchanged: G was already a wave after F.
- **D's walk inputs.** The trip model's per-node `trips` are unchanged; the generic task-switch walk
  (`SimInputs.walkSeconds`, default `rules/base.json` `walkSeconds` = 5) is engine (F, G), not D. D still
  supplies the `moveSpeed` multiplier through `modifiedValue`.
- **Vitest include resolved.** SGS-015 extended `vitest.config.mts` `include` with `components/**/*.test.ts`
  and put the pure helpers in `components/apps/aoe4-build-order/chart-rows.ts`. J's mapping test is a
  `components/**/*.test.ts` or `lib/**/*.test.ts` file; no config change.
- **No hydration helper exists.** The first plan said SGS-012 adds one to `acceptance/helpers.ts`; it did not
  (helpers.ts exports only fight helpers). J follows the existing pattern
  (`page.waitForLoadState('networkidle')` before clicking, `page.waitForResponse` on the POST, as in
  `acceptance/combat-simulator-battles.spec.ts`).
