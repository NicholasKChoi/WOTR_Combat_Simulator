Evidence: strategy-game-sim. Drive log `drive-20261118-2153.md` pass 4 (session e2f2a8ee): the SGS-211
acceptance-test was launched in the background at 00:18 while SGS-212's ran. SGS-212's returned at
00:20:41; the manager replied "I'm holding it for SGS-211's acceptance run so both go through the batch
gate together" at 00:20:46, which ended the pass. The SGS-211 agent's transcript stops at 00:30:46, the
session end, with `finished: null` in its meta file. Run log `run-20261118-2325.md` 00:31 "resumed after
interruption"; pass 5 relaunched it ($0.55 lost, $0.84 relaunch, ~13 min). Prior window: the M11 designer
and the SGS-192/197 implementers (retro 2026-11-18 pattern 2, ~$6 lost, a 12 h stall).
Root cause / escape point: agent behavior; a rule exists and does not fire. No gate applies.
RCA: manage.md:176-180 says "Launch an agent in the foreground when no other agent is running" and
"Never end the pass's turn while one is still running". The first sentence sends every agent launched
while another runs to the background. When a background agent's notification arrives, the manager
handles it and writes a status line, and in `claude -p` any text reply ends the turn. Nothing in the rule
gives the manager a check it can run, and nothing in `drive-loop.sh` notices an unfinished agent. The
2026-11-18 retro's proposal went in as a comment on closed #17 (00:54 11-19), not a tracked issue, so no
engine change landed. Pass 5 (session 708f5bc8) then launched all 7 agents in the foreground and lost
none, which shows the edit works: with foreground launches the 00:20 reply could not have been written
while SGS-211 ran, and the 11-16 losses had the same shape.
Confidence: high - repeat after an earlier fix, three windows of evidence, and the drive-loop half of
the edit detects it mechanically.
Proposal (engine): Issue draft: retro-20261121-issue-1.md "Drive passes still end their turn with a
background agent running (regression of #17)". manage.md: never `run_in_background` an agent in a drive
pass, launch parallel ones together in one message; `drive-loop.sh`: count the pass session's subagents
whose meta has `finished` not true, log `issue: pass ended with <n> agents unfinished`, treat the pass
as changed.

### 5. Criteria and tests aim at a layer that cannot observe them
Evidence: strategy-game-sim SGS-210 spec-gate 2 (a computed-style check on a portaled, hover-mounted
popover, with no acceptance spec allowed; a `Results` prop no test can reach), SGS-211 spec-gate 2 gap 1
("closed after a reload", but the page does not keep the editor text), SGS-212 review 6 finding 3

recharts SVG), SGS-206 RS2 (a hook unit test node vitest cannot run).
Root cause / escape point: spec gap from a missing input. Escape point: ticket (and implementer for
212), caught at spec-gate and review.
RCA: ticket.md says criteria must be "observable and testable", and spec-gate item 2 checks it, but
nothing the ticket agent or the implementer loads says what this repo's test layers can observe. The
facts are repo-specific: `vitest.config.mts` includes only `*.test.ts` and sets no DOM environment, and
components are tested with `renderToStaticMarkup` (12 test files), so there are no effects, portals,
hover, post-event state, computed style or recharts SVG at the unit layer. Each writer assumed a layer
could see what it could not. A CONTEXT.md section (loaded by ticket, spec-gate, implementer and review)
gives that input: 210's writer would have put the popover lines in a pure function (what RS1 did), 211's
would have dropped the reload, 212's implementer would have pinned `saving` in the acceptance spec, and
198 and 206 would have picked the acceptance layer. It changes no gate.
Confidence: high - six occurrences across two windows with one missing input; a text edit to a file
every relevant agent already loads.
Proposal (repo): `CONTEXT.md` - add after the Design docs section:
```markdown
## Test layers

What each test layer here can observe. A criterion names a layer that can see it; logic only a test
can check moves into an exported pure function a unit test calls.

- Unit (`npm test`, vitest): only `*.test.ts` under `utils/`, `lib/`, `components/`, in Node with no
  DOM. Components are tested with `renderToStaticMarkup`: one static render, so no effects or layout
  effects, no portals, no hover or focus, no state an event sets (an in-flight save, an open form), no
  computed style or layout (CSS modules give class names only), and no recharts SVG. Unexported
  functions and component locals are out of reach.
- Acceptance (`npm run acceptance`, Playwright, Chromium, `acceptance/*.spec.ts`): the real page on
  `next dev`. Computed styles, layout, hover and focus, held requests, and state after events. Text
  edits settle after the auto-run pause: wait for `auto-run-status` `data-status` before asserting on
  the converted build.
- A reload does not keep the editor text: the page starts from the first build, or the build `?n=`
  names, and restores only a pinned run from storage.
```
