## Design questions

| # | outline(s) | question | why the design does not settle it |
|---|------------|----------|-----------------------------------|
| 1 | D, E, G | Who owns the debounce and the settled input? `useAutoRun({ request, hold })` takes a request "null when the settled input is invalid", so settling happens before the hook, yet the hook owns `AUTO_RUN_DEBOUNCE_MS` and returns `flush()`. Does the hook take the live text and duration (plus the catalog) and return the settled text, duration, conversion and issues, or does the page debounce and the hook only fire? Issues, the request and Save must all derive from the same settled value. | C6 signature and the "Settled input" rule point in opposite directions; "Left to tickets" only leaves the timer mechanism open, not its owner. |
| 2 | D, E | Where does `postSimulation` (and `errorMessages`) live once the hook needs it? A module under `components/` cannot import from `pages/apps/aoe4-build-order.tsx`. Options: inside `use-auto-run.ts`, or a new `components/apps/aoe4-build-order/simulate-client.ts` the page's pin restore also imports. And under the new rules a 400 yields `serverIssues: BuildOrderIssue[]`; is `errorMessages` kept only for non-400 wording? | C6 says only "`postSimulation` gains an `AbortSignal` parameter"; the module table does not list it. |
| 3 | D | How are the `useAutoRun` rules unit-tested? Vitest has no DOM environment (`vitest.config.mts` sets none; no jsdom, happy-dom or `@testing-library/react` installed); existing component tests use `renderToStaticMarkup`, which runs no effects. Either add dev dependencies (`jsdom` + `@testing-library/react`, plus a per-file `// @vitest-environment jsdom`) or put the state machine in a pure controller the hook wraps and test that with fake timers. | "Left to tickets" asks for hook tests "with fake timers and a stubbed fetch" but no harness exists, and adding test dependencies is a repo-level choice. |
| 4 | D | Does `retry()` bypass rule 2 (key equals `inflightKey`) and rule 4 (key equals `rejectedKey`)? `failed` clears `inflightKey`, so rule 2 cannot match; confirm retry is exactly "rule 5 now" and is a no-op unless status is `failed`. When `hold` goes false after a `?b=` load, does the hook fire immediately (like first load) or after the debounce? | The retry row says "Fire step 5"; the `hold` release is described only from the page side ("Settle and fire at once"). |
| 5 | E | When is `tab-results` enabled on narrow screens? The design says "once a result or status exists, as today", but today it is `result !== null \|\| pin !== null` and a status exists from first load (`running`). Is Results enabled while the first run is `running` (it would show only `auto-run-status`), or only once a result or pin exists? | The rule names a condition ("status exists") that is always true under auto-run. |
| 6 | E | Where do `auto-run-status`, `simulation-error` and `simulation-retry` render? The status table puts the dim on `results-last-good` (results panel) and `IssueList` "beside the editor", but on narrow screens with Build selected the user cannot see a status that lives only in the results panel. Is `auto-run-status` in the results panel, the run bar, or both; and does `simulation-error` stay under the editor as today? | Placement is given for issues only. |
| 7 | F | In split mode, is the Text/Table toggle always enabled? Today `viewDisabled={shownTab === 'results'}`; in split both panels show, and after a resize back to tabs `tab` may be `results`. | The layout table does not mention `viewDisabled`. |
| 8 | F | The sticky `.timelineColumn` rule (`top: var(--run-bar-height)`, `max-height: calc(100vh - ...)`) sits inside the same 1200 px media query as `.resultsSplit`. When `.resultsSplit` moves to 1800 px, does the sticky timeline move to 1800 px too, and below 1800 px is the stacked timeline height-capped? | The design moves only `.resultsSplit`. |
| 9 | C, G | The rate limit is shared by the whole Playwright run: every request comes from `127.0.0.1` to one file store under `test-results/`, so the suite may make at most 30 saves per hour before unrelated specs get 429, and the 429 spec needs 31. May specs send a distinct `x-forwarded-for` per spec (honored by `clientKey`, so this also tests the header path), or should Playwright set a higher limit through an env var? (An env-tunable limit would change C5.) Also: is a 429 test required in acceptance, or is the Vitest boundary test enough? | C5 fixes the numbers; the acceptance layout does not address the shared budget. |
| 10 | C | How do route unit tests inject `createMemoryBuildStore`? `buildStoreFromEnv` is memoized per module and handlers export only `default` and `config`. Options: a test-only setter, `vi.mock('../../../lib/aoe4-build-order/build-store')`, or a handler factory. | "Left to tickets" asks for handler tests against the memory store but names no seam. |
| 11 | C | jscpd (`minTokens 70`, `threshold 0`, covering `pages/api/aoe4-build-order`) may flag the 405 + `Allow` and plain-object checks the new routes share with `simulate.ts`. May C extract a shared helper module (e.g. `lib/aoe4-build-order/api-route.ts`) and edit `simulate.ts` to use it? | The designer flagged the risk; the module table has no such module. |
| 12 | H | How does `scripts/smoke-preview.mjs` read "the first entry of the page's shipped builds"? `listBuilds()` lives in TypeScript (`lib/aoe4-build-order/builds.ts`, extensionless imports, JSON imports) that plain Node cannot import, and `tsx` is not installed. Options: import `data/aoe4-build-order/builds/english-1tc.json` directly (duplicating the order in `builds.ts`), make the script `.ts` and add `tsx`, or fetch the page and read the select. | The design says "read from the same data the page uses" without a mechanism. |
| 13 | J | Does "a pinned series' item follows its current series' item" mean order only (the pinned item sits after its current item, as `legendItems` does today) or toggle linkage (hiding `Gold` also hides `Gold (pinned)`)? If linkage: can `Gold (pinned)` still be toggled on its own; what does clicking it do while `Gold` is hidden; and are pinned-only series (no current series of that key) independent? Or should the doc sentence change instead of the code? | The backlog report reads it as linkage; the code and the sentence's position (after the click rule) support either. Not covered by the M6 design. |
| 14 | J, E | What should happen to an invalid unsaved number in the step table? Today it never reaches the text (`setNumberField`/`setTriggerNumber` return the step unchanged), so under auto-run the status stays `current` while the field shows a value the run ignores. Options: keep drafts in page state keyed by field and step index so they survive the toggle (dropped when the text changes elsewhere); disable the view toggle while a draft is invalid; or accept the loss and mark the field `aria-invalid` with a message. Should an invalid draft count as invalid settled input (dim, no POST)? | Neither the M6 design nor `docs/aoe4-build-order.md` defines draft state. |
| 15 | B | What key does `bumpCounter(key, windowStart)` take? C1 says counters live at `<env>/rate-limit/<clientKey>.json`, but no C1 function builds that key (only `savedBuildKey`), and the stores are constructed with an env. Does the store prefix the env and path (`key` = `clientKey`), or does C5 build the full key (then C1 needs a `rateCounterKey(env, clientKey)`)? And what env does `createMemoryBuildStore()` default to? | C1/C2/C5 name the layout but not who composes it. |
| 16 | E | Is "abort the restore request in the effect cleanup" the accepted fix for the pin restore double POST? Under Strict Mode it still sends two requests (the first aborted), and Strict Mode is off in this repo (pages router default, no `next.config.*`), so no spec can observe it today. Or must the restore send exactly one request (defer the fetch past the cleanup, or dedupe at module scope)? | The backlog item names the symptom only; the design does not mention the pin restore. |
