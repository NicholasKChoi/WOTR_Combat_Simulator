## Design questions

None needs the owner. Each is answered by the existing code or docs and is stated here so the ticket author
specifies it instead of re-opening the design. All come from one root cause: the design's page-side Starting state
and Revisions were read from a stale local checkout (87f0cd7), not origin/main 7d74800. On origin/main
`chart-markers.ts`, `chart-zoom.ts`/`use-chart-zoom.ts` (per-chart drag zoom and pan, SGS-197), the shared
`MarkerControl` with per-kind hide toggles (SGS-195, `hiddenKinds` in `results.tsx`), and `page-help.tsx` (SGS-199)
all exist.

| # | outline(s) | question | why the design does not settle it |
|---|------------|----------|-----------------------------------|
| 1 | B | Where `ChartTimeMark`, `TIME_MARK_COLOR` and the label text helper live. Recommended: `chart-markers.ts` (next to `MARKER_COLORS`, `markerLabel`, `estimateLabelWidth`), not `chart-rows.ts`. | C2 places them in `chart-rows.ts`, believing marker colours live there. `ARCHITECTURE.md` line 30 says `chart-markers.ts` "is the one home of every chart marker rule ... No other module defines a marker colour"; `markerLabel` and `estimateLabelWidth` are imported from `chart-markers.ts` by `line-chart.tsx`. Putting the colour in `chart-rows.ts` breaks that rule unless ARCHITECTURE.md is reworded. |
| 2 | B, C | How the mark behaves on a zoomed Population chart. Recommended: drawn only when `shown.from <= at <= shown.to` (the `inWindow` rule markers, dots and the step band use; UI doc line ~193), and `timeMarkLabelPosition` takes the window: `(at, end, plotWidth, labelWidth, origin = 0)` with `at - origin` against `end = shown.to - shown.from`, matching `placeMarkers`'s `origin` parameter. | C2 says "No zoom or pan exists; the x domain is the run's times" and gives `timeMarkLabelPosition(at, end, plotWidth, labelWidth)` with no origin; with a zoom window the given formula flips the label wrongly and a mark outside the window would draw past the axis (`allowDataOverflow` is on while zoomed). |
| 3 | B | Whether the shared Markers control's per-kind hide toggles affect the mark. Recommended: no; the mark is drawn whatever kinds are hidden, including when every kind is hidden or the run has no markers (so no control is drawn). | D8 says the mark "cannot be hidden" and is not in the Markers legend, but the design believed the legend had no hide toggle. The answer follows from D8; it is listed so B's tests and UI-doc text cover the "all kinds hidden" case. |
| 4 | B | Whether a pointer-down on the mark's bottom label starts a zoom selection. Recommended: yes, as anywhere in the grid; the label is SVG text inside the plot, not one of the excluded areas (axes, top marker label rows, legends, zoom bar). | The design's bottom-label placement assumed no drag zoom; the UI doc's zoom-start rule (line ~187) names the top marker label rows only. |
