# Plan: M10 (2026-11-16)

Planned against design `design/M10.md` (approved 2026-11-16; OD1 = 1200 px, OD2 = A, so C8/B8 and the
notice are out) and main `6411526` (read in the main checkout, read-only). No M10 ticket exists in
TASK-GRAPH.md; nothing below duplicates existing work. The BACKLOG.md item "Remove mobile support for the
AoE4 build-order page" (which also absorbed the 360 px chart-tooltip item) is planned here as the whole
milestone and is removed from BACKLOG.md.

Delivery follows the design's three steps. Step 1 (specs to desktop viewports) is split by spec file into
five outlines (A to E) that each own a disjoint set of spec files, so they rebase without conflicts. Step 2
is one outline (F). Step 3 is one outline (G).

Two placement choices differ from the design's wording; both keep the design's end state (see Spec gaps):
the JS-disabled "server render is two columns" case lands with F, not in step 1, because it fails on
today's main; and F (not the last step-1 ticket) removes `SPLIT_MIN_WIDTH`, `TABS_VIEWPORT` and `showTab`,
so the step-1 outlines can stay parallel instead of needing a "last" one.

## Spec gaps

1. **The B5 "server render is two columns" rewrite cannot land in delivery step 1.** The design's inventory
   lists it as a step-1 rewrite of `aoe4-split-layout`, and step 1 is meant to pass on today's main. It
   does not: `useSplitLayout`'s server snapshot is `false`
   (`components/apps/aoe4-build-order/use-split-layout.ts` line 13), so with JavaScript disabled today's
   page renders the tabs layout and `workbench-split` is absent. Resolved in this plan without changing the
   design's end state: B deletes the old "first paint matches the server render and ends split" case, and F
   adds the rewritten case together with the code that makes it pass. No owner input needed; the designer
   may update the inventory row.
2. **Where the old helpers are removed.** The design has "the last" step-1 ticket remove
   `SPLIT_MIN_WIDTH`, `TABS_VIEWPORT` and `showTab` and add `MIN_SUPPORTED_VIEWPORT`. With step 1 split
   into parallel outlines there is no single last one, and B, C, D need the new constant first. This plan
   has A (a root) add `MIN_SUPPORTED_VIEWPORT` and F remove the three old helpers once no spec calls them.
   Same end state, shallower graph. No owner input needed.

No criterion or delivery step was left ungrounded.
