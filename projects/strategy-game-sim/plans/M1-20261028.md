## Spec gaps

1. **N for the WOTR Monte Carlo (open question, not answered here).** Default N and max N are
   undecided. E is blocked on it; A leaves it as TBD; the answer also fixes whether N is a request
   field (then D/E must cap it for S3) or a server constant.
2. **WOTR rules vs. published game (M1.1).** The code departs from the board game in several places
   (no 5-die combat cap, no leadership cap, fixed casualty heuristic, fight-to-elimination, no
   cards/siege). The owner must say which are intended simplifications and which are bugs. Any rule
   the owner changes becomes a new ticket judged against W1; none is planned here.
3. **Input bounds (M1.1/M1.5).** UI allows 0-9 regs, 0-9 elites, 0-5 leaders; the server enforces
   nothing; PR #11 uses 10/10/5 per field. The published game caps an army at 10 units total. Owner
   picks per-field and total caps, and what happens when a side starts with 0 units (reject with 400,
   or report an immediate result).
4. **Outcome set (M1.1/M1.6).** "Outcome frequencies" is not defined: win/loss/mutual-elimination only,
   or also rounds-to-finish and surviving-unit distributions. Doc A must settle it before E.
5. **StarCraft map pool source and edge wording (M1.2/M1.8).** No source/season is recorded for
   `mapArray`; the all-struck message text and whether the previous pick counts as "struck" for the
   exhaustion check need the owner.
6. **`/api/models/army` is an accidental public route (M1.7).** `pages/api/models/army.ts` sits under
   `pages/api/`, so Next.js exposes `/api/models/army` (it has no default export). CONTEXT.md's
   component paths name this file, so moving it is a contract-level choice: owner decides whether F
   moves the model out of `pages/api/` (and CONTEXT.md paths are updated) or documents it as not a
   supported endpoint.
7. **"Reviewable" API surface (M1.7).** Plan assumes doc + exported TypeScript types. If the owner
   wants something else (e.g. a JSON schema checked in acceptance), F changes.
8. **`ARCHITECTURE.md` is a styleSource but is not on `main`.** It exists only on the unmerged
   `add-architecture-doc` branch (commit 12f54f6). Implementers branching from `main` will not have it.
